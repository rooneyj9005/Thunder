Server Setup

Want to host Thunder for your group? Here's how to get a server running.

The short version

Thunder uses a tool called packwiz-installer-bootstrap that automatically downloads all the right mods into your server folder. You don't need to manually copy anything. Run one command and it handles the rest. It even knows to skip client-only mods like minimaps so your server isn't loading things it doesn't need.

What you'll need

  • Java 17 or newer.
  • A Forge 1.20.1 server (Forge version 47.4.13). If you haven't set one up before, grab the installer from the Forge downloads page and run it once to generate the server files.
  • At least 6 GB of RAM for the server. 8 GB is better if you're expecting more than a few players online at once.

Setting it up

1

Get the installer

Download packwiz-installer-bootstrap.jar from the releases page and drop it into your server directory, the same folder where forge-*.jar lives.

2

Run it

Open a terminal in your server directory and run:

java -jar packwiz-installer-bootstrap.jar -g -s server https://thunder.john.rooney.scot/pack.toml

That's it. The installer reads the pack definition, downloads all the server-side mods, and puts them in your mods/ folder.

3

Start the server

Launch Forge as you normally would. All the Thunder mods are now installed and ready to go.

Pterodactyl / Pelican panel

If you're running a Pterodactyl or Pelican hosting panel, Thunder ships with a ready-made egg template that handles everything for you - Forge installation, mod synchronisation, and automatic updates on every restart.

1

Import the egg

Download pterodactyl.json from the repository. In your panel, go to Nests → Import Egg and upload the file.

2

Create a server

Create a new server using the imported Thunder egg. The defaults are already configured - Forge 47.4.13, Minecraft 1.20.1, and the correct packwiz URL are all pre-filled. Select the Java 21 Docker image (recommended) and allocate at least 6 GB of RAM.

3

Start the server

Hit install, then start. The egg's install script sets up Forge automatically, and the startup command runs packwiz-installer-bootstrap before every launch to keep mods in sync. No manual file management needed.

Install command: bash install.sh --container
Startup command: bash startup.sh --container

Advanced: Panel administrators can use the Installation Script Source variable to choose between the latest stable release or the bleeding-edge main branch installation script.

Note: Server owners (non-admin users in the panel) can see the modpack settings but can't change the packwiz URL, modloader, or Forge version. Only panel administrators can modify those values.

Standalone server (Linux)

If you're not using a hosting panel, the repository includes an install script that sets up Forge and downloads everything for you. You'll need curl, jq, and Java 17+ installed.

1

Download and run the install script

Create a directory for your server and run:

mkdir thunder-server && cd thunder-server && curl -sSfL https://raw.githubusercontent.com/rooneyj9005/Thunder/main/install.sh | bash

This installs Forge, downloads packwiz-installer-bootstrap.jar, and fetches the startup script. No manual file management needed.

2

Accept the EULA and start

echo "eula=true" > eula.txt && bash startup.sh

The startup script syncs the modpack via packwiz before every launch, so mods stay up to date automatically.

Standalone server (Windows)

The repository also includes PowerShell scripts for Windows servers. You'll need Java 17+ installed and available on your PATH.

1

Download and run the install script

Download install.ps1 into an empty folder and run it in PowerShell:

.\install.ps1
2

Accept the EULA and start

Set-Content eula.txt "eula=true"; .\startup.ps1

Keeping things up to date

When a new version of Thunder comes out, just re-run the installer command from step 1. It figures out what's changed, downloads new mods, updates existing ones, and removes anything that's been dropped from the pack.

Tip: Add the installer command to the top of your server start script, before the line that launches Forge. That way your mods are always in sync every time the server starts. The installer is fast and if nothing has changed, it finishes in a couple of seconds.

A few recommended tweaks

These aren't required, but they'll help performance on a modded server:

  • In server.properties, set view-distance to 8. Less chunk generation means more headroom for mod logic.
  • Set simulation-distance to 6 for better tick performance.
  • Don't forget to accept the EULA. Set eula=true in eula.txt or the server won't start.

Server administration tips

Thunder includes several mods designed for server operators. Here's a quick overview of the ones you'll use most.

Permissions with LuckPerms

LuckPerms handles all permissions on the server. Use /lp editor in-game to open a web-based editor where you can create groups, assign permissions, and manage players. The LuckPerms wiki covers everything in detail.

Tracking griefing with GriefLogger

GriefLogger records every block placement and removal. If a player reports griefing, use the in-game lookup commands to check the history of any block. You'll see who placed or broke it and when.

Base protection with SecurityCraft

SecurityCraft lets players protect their own builds with reinforced blocks, keycard doors, laser grids, and security cameras. As a server operator, it means less moderation work — players can defend their own stuff. The included config file (config/securitycraft-client.toml) ships with sensible defaults.

Voice chat

Simple Voice Chat runs on port 24454 (UDP) by default, in addition to the standard Minecraft port (25565). Make sure this port is open in your firewall and forwarded if needed. Players connect to voice automatically when they join the server.
